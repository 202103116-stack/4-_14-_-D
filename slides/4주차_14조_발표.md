## 슬라이드 2 — 미션: 방과후 10대가 많이 머무는 구에 공간을 연다
- **미션(고정)**: 의사결정자 = 청소년정책 담당자 / 결정 = 방과후 청소년 공간을 새로 열 자치구 / 범위 = 15~18시 · 10대 → **15·16·17시 3개 시간대**(시간대 X = X시~X+1시라 18시 버킷은 범위 밖)
- **두 지표**
  - 절대 = 합계: 10대 합계 — "얼마나 많이 머무나"(명)
  - 비중 = 비율: 10대 ÷ 전 연령 — "얼마나 몰려 있나"(%), 분모 = 같은 시간대 전 연령대 합계
- **가설(분석 전)**: 방과후 10대는 사는 곳이 아니라 학원·학교가 몰린 구에 머물 것이다
  - 절대 상위3에 학원가 강남·양천·노원이 다수 들어갈 것
  - 비중은 번화한 학원가(강남·송파)보다 학원가 + 주거지인 노원에서 두드러질 것
- **반대 결과 수용(미리 정해 둔 규칙)**: 학원가 밖의 구가 상위에 오르면 가설을 기각하고 상업시설·환승거점·통근 같은 비학업 요인으로 설명을 바꾼다 → 3장에서 실제로 발동

## 슬라이드 3 — 데이터와 함정: 숫자를 믿기 전에 확인한 세 가지
- 데이터: 서울시 생활인구(가공) 3,860행 × 5열 · 25개 구 × 24개 시간대 × 6개 연령대 · 2026-04-15 하루치
- **함정 1 생활인구 ≠ 거주인구**: 그 시각 그 구에 있던 사람 수. 다른 구에서 통학해 온 학생도 함께 잡힌다
- **함정 2 오류가 심어진 데이터**: 중복·결측·음수·고값·콤마 표기를 일부러 넣었다. 그대로 더하면 틀린다

- → 전부 고치지 않고, 15~17시 범위에 영향이 있는지부터 확인했다

## 슬라이드 4 — 정제 순서: 앞 단계가 뒤 단계의 입력을 깨끗하게 만든다 ★1
다이어그램(8단계, 위에 단계 묶음 표시):

| 묶음 | 단계 | 적용 범위 | 이 순서인 이유 |
|---|---|---|---|
| 진단 | 0 사전 진단 | 변경 없음 | 범위 안 영향부터 센다 |
| 형식 정리 | 1 공백 제거 | 전체 | 컬럼명 공백에 코드가 깨지지 않게 |
| 형식 정리 | **2 숫자 변환** (핵심 판단 ①) | 전체 | 숫자가 돼야 합계·중복·음수를 판단 |
| 명백한 오류 교정 | 3 중복 제거 | 전체 | 합계·평균이 부풀지 않게 |

## 슬라이드 5 — 핵심 판단 두 가지: 숫자 변환, 음수 처리 ★1
**① '1,234'는 더할 수 없다 (숫자 변환)**
- 원본 → 정제 후: `"1,234"` → 1234 / `"1234"` → 1234 / `"-"`·빈칸 → NaN(결측)
- 문제: 콤마 있는 값과 없는 값이 섞여 열 전체가 문자열 → 합계 불가 (360건, 범위 안 10대 6건)
- 처리: 콤마를 지우고 숫자형으로 변환, 문자 '-'와 빈칸은 NaN
- 검증: 변환 후 NaN 195건 = 원래 '-'·빈칸 195건 → 변환 때문에 잃은 값 0건(assert)

**② 인구는 음수일 수 없다, 규칙은 둘 (음수 처리)**
- 원본 → 정제 후: −9990 → NaN(결측) / 그 밖의 음수 → abs()로 부호 복원 (예: −417 → 417)
- 근거: −9990은 인구 범위를 벗어난 오류코드. 나머지 음수의 절대값(417~7,804)은 정상 인구 범위 안
- 처리: −9990(2건)은 결측으로, 나머지 23건은 부호만 되돌림 — 행은 지우지 않음
- 영향: 범위 안 2건 모두 분모(전 연령) → 10대 합계는 그대로, 비중의 분모만 바로잡힘

## 슬라이드 6 — 어디까지 고칠까: 틀린 값은 전체, 모르는 값은 범위 안만 ★2
- **판단 기준은 하나: 이 값은 '틀린' 값인가, '모르는' 값인가?**
- **틀렸다 → 전체 표에 적용 (명백한 오류 교정)**: 공백 제거 · 숫자 변환 · 중복 제거 · 음수 규칙
  - 인구가 음수일 수 없다는 사실은 15~17시에만 참인 게 아니다
  - 정제된 표는 24시간 히트맵에도 다시 쓰인다. 범위 밖 오류를 남기면 그 그래프가 오염된다
- **모른다 → 범위(15~17시) 안에서만 (모르는 값 추정)**: 결측 보정 22건
  - 범위 밖 결측은 절대·비중 어디에도 쓰이지 않는다
  - 채울수록 근거 없는 추정값만 늘어난다 → 범위 밖 결측 159건은 그대로
- 손대지 않은 것도 이유와 함께 기록: 동대문구 새벽 고값 18건(범위 밖) · 범위 밖 결측 159건 · 기준일자(단일 날짜, 형식 이상 없음)

## 슬라이드 7 — 정제 결과: 범위 안 문제는 0건, 행 수는 기대값과 일치 ★3
- 왼쪽: **이슈별 건수 단계별 추적표** 이미지(`slides/정제_추적표.png`, 원본 `slides/정제_추적표.html`)
  - 회색 ① 원본 / 파랑 ② 중복 제거 후 / 초록 ③ 정제 후
  - 초록 테두리 = 정제로 해결, 주황 = 범위 밖이라 의도적으로 유지(결측 159·고값 18), 빨강 = 결과를 왜곡하는 값(10대 중복 7행)
  - 해설 A~E: 중복 7행이 10대 합계를 부풀림 / 10대 결측은 처음부터 0건 / 분모 결측 22건 → 0건 / 남은 결측 159 = 180 − 22 + 1 / 동대문 고값 18건 수정 안 함
- 오른쪽: **필터 전 → 후 행 수**
  - 전체 3,860 → 3,600 (중복 260행 제거)
  - 범위 · 전 연령(분모) 485 → 450 (= 25구 × 3시간 × 6연령)
  - 범위 · 10대(분자) 82 → 75 (= 25구 × 3시간)
  - 기대값과 정확히 맞아서 필터 조건(15~17시)이 맞다는 것도 함께 검증. 0행이 나오면 코드보다 조건을 의심

## 슬라이드 8 — 분모 결측을 보정하자 비중 순위가 크게 바뀌었다 ★4
- 왼쪽: 순위 이동 그래프(보정 안 함 → 보정함)
  - 성북구 1→6위(▼) · 영등포구 2→1위(▲) · 중랑구 3→3 · 서대문구 4→4 · 금천구 5→5 · 양천구 6→13위(▼) · 노원구 7→2위(▲)

- 재현성: 팀원 3명이 각자 Colab에서 "런타임 → 다시 시작 및 모두 실행"으로 같은 숫자(75행, 상위5 등)가 나오는지 확인 → `logs/재현성_확인표.md`
- AI 활용: AI에게 "몇 건 지웠는지"가 아니라 "왜 지웠는지/왜 안 지웠는지"를 매 단계 설명하게 하고, 직접 실행해 검증한 뒤에만 채택 → `logs/AI활용기록.md`
- 18시를 왜 뺐나: 시간대 X = X시~X+1시. "09~18시 근무"가 18시를 포함하지 않는 것과 같은 논리 → 범위 행 수가 25구 × 3시간 = 75행으로 정확히 맞음
